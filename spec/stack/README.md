# The Stack's wire shapes

The shapes Home builds against, declared once and defined nowhere else:
the role request and reply headers, the event feed envelope with its ten
ids, the health item, the settings declaration (a `SettingsKey` from
`spec/schemas/settings-key.schema.json` plus the Stack's value half), the
precious-state declaration, the speech session's `SttWireEvent` and
`SttTranscribeResponse` (mirrors of `spec/voice/ts/sttTypes.ts`,
STACK-94b; the Stack adds nothing to them), and the job (`StackJob`,
STACK-13a: the unit of work Home submits, watches, cancels and reads).

Each is a JSON Schema 2020-12 file under `../schemas/` (flat, alongside
every other record and package shape), a hand-written Zod mirror under
`ts/` the Stack's backend imports, and fixtures under
`../fixtures/<shape-name>/` (`valid-*.json`, `invalid-*.json`).
`../tests/ts/stack-fixtures.test.ts` validates every fixture against both
the schema (Ajv 2020) and the Zod mirror and fails when they disagree, so
the two cannot drift.

Landed here at `spec-v0.1.0` (RF-05b), moved whole from
`stack/backend/src/spec/`, which held these in exactly this shape as a
temporary home so the move would be a copy, never a translation. The
Stack's own backend now imports `@maipai/spec` for these instead of
carrying its own copy (a later Session A item; this move only lands the
shapes here).

The Zod mirrors are hand-written, not generated by `spec/scripts/gen-ts.ts`
- unlike the record schemas in `../schemas/`, which do flow through that
pipeline into `../gen/ts/`. These 9 schemas were deliberately left out of
that pipeline for now: folding them in is a separate decision (it would
also need Python codegen the Stack, a TS-only backend, has no use for)
and isn't part of this move.
